# activity-slack-report

Compute earliest/latest task times, total/free slack, binding predecessor evidence and one longest-chain witness with explicit finish-to-start lags.

For release coordinators reviewing a small dependency schedule before setting a deadline.

## Quickstart

Linux/Python3.10+; public source installation, no external service or runtime dependencies.

```sh
git clone https://github.com/nripankadas07/activity-slack-report.git
cd activity-slack-report
python -m venv .venv
. .venv/bin/activate
python -m pip install .
activity-slack-report example.json
```

The command prints deterministic JSON. Invented example finishes at10; design has4 slack and buy→build→review is the longest chain.

All input examples are invented. The tool reads one UTF-8 JSON file, at most1MiB, rejects duplicate keys/nonfinite numbers/unknown fields and never modifies the input. Exit0 means a completed nonfinding result; exit1 means a documented finding (infeasible deadline, unexpected deadlock, no route or failed inclusion). SQL reports all row outcomes with exit0. Exit2 means malformed/unsupported input with stderr and no partial report. Petri exit3 means incomplete exploration with no deadlock found; a found deadlock uses exit1 even if exploration is incomplete.

## Input and interpretation

Start with the exact structure in [example.json](example.json). [Expected JSON](example-output.json) is generated by the validated example.

Acyclic activity-on-node finish-to-start model; integer durations/lags from0..10^9, unlimited parallel resources, project starts at0. Optional deadline0..10^15 sets backward pass; a too-early deadline yields negative slack, not an invalid graph. No calendars, resource leveling, start-to-start links, negative lags or estimates of real completion. Up to200 tasks and2000 distinct links. A cycle rejects without a partial schedule. The longest chain relates to minimum finish, while deadline slack may differ.

Identifiers are nonempty strings up to80 characters. Integer bounds exclude booleans. Required keys and types are validated. These are model diagnostics, not automatic changes to a live system. The report describes supplied data only.

## Why this small tool

A list of durations hides which predecessor sets the finish and which tasks can move without delaying the project.

capacity-cut-report allocates pool capacity by max flow, task-queue runs asynchronous work, and systemd-order-audit checks ordering. This computes time and deadline slack, with no execution or resource assignment.
